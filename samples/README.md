# Sample binlog

A self-contained demo so you can try the viewer without supplying your own file.

## Getting the demo binlog

**`mysql-bin.000001`** (~52 MB) — generated from MySQL 8.0 against
**`demo-workload.sql`** (kept here so the binlog is reproducible and you can
see exactly what produced it). Synthetic data only — safe to commit/share.
Named like a real MySQL binlog so the directory scanner discovers it
(it matches files named `<base>.<4+ digits>`).

This file ships as **`sample-binlog.tar.gz`** in the latest [GitHub release](https://github.com/adrijshikhar/binsight/releases).
To use it locally:

```sh
# Option 1: Download from release
cd samples
tar xzf sample-binlog.tar.gz
# Extracts mysql-bin.000001

# Option 2: Regenerate locally (requires Docker)
make sample
```

- **`mysql-5.5-nogtid.binlog`** (~3 KB) — a MySQL 5.5 binlog (copied from the
  conformance corpus). 5.5 predates GTIDs, so it has **no GTID events** — useful
  for exercising the GTID-less path (e.g. the grouped Events view labels its
  transactions by a per-file ordinal `txn 1, 2, 3…`, since there is no GTID seq).

It is deliberately large and varied so every part of the UI is populated and
the viewer's value on real, big binlogs is obvious:

- **Overview / metrics** — hundreds of thousands of events, real byte
  throughput, a multi-second time span (the chart shows activity over time).
- **Tables** — `customers`, `products`, `orders`, `order_items`, `audit_log`
  with different insert/update/delete mixes.
- **Schema/DDL** — CREATE / ALTER / CREATE INDEX / TRUNCATE / DROP churn.
- **Anomalies** — it intentionally trips three detectors:
  `bulk_row_event` (one event with 350k rows), `huge_txn_rows` (a ~700k-row
  transaction), and `long_txn` (a transaction held open > 60s).

## Try it

```sh
make run            # serves ./samples by default
# or directly:
go run ./cmd/binsight serve samples
```

Then open the printed URL. For your own binlogs: `make run DIR=/path/to/binlogs`
(or `BINLOG_DIR=/path docker compose up`).

> Seeing stale files from an earlier run? The viewer keeps a persisted index.
> Clear it with `make clean-data` (local) or `docker volume rm
> binsight_viewer-state` (Docker).

## Regenerate

Requires Docker (offline maintainer step):

```sh
make sample
```

This is **not** the conformance corpus — that lives in
`internal/testdata/corpus/` (generated by `make corpus`). This file exists
purely so a first-time user has something to open.
